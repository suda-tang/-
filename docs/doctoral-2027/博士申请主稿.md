# 2027年博士申请主稿

用途：不同导师申请时删选、调整的长主稿。首次联系可以保留研究问题、关键工作和博士计划，完整技术细节作为附件。方括号按真实信息替换；不能原样发出占位内容。

邮件主题：2027年博士申请咨询｜唐秋鸣｜苏州大学音乐教育硕士｜音乐学习中的智能反馈与课堂交互研究

尊敬的[导师姓名]老师：

您好！我是唐秋鸣，苏州大学音乐学院音乐教育专业钢琴方向2024级硕士研究生，目前研三，拟申请2027年攻读博士学位。硕士期间，我一直围绕一套持续研发的钢琴演奏教学辅助系统开展工作，也在苏州星海高级中学参与人工智能赋能音乐教育的试点。写这封信，是想向您介绍我从这个项目里逐渐找到的研究问题：当系统能够指出一个音错了、替学生定位片段，甚至把下一步练习安排好，学生究竟是在学会自己判断，还是只是在更顺利地依赖提示？我希望博士阶段把这个问题研究清楚。

我最初并不是从设计一个“智能课堂”开始的。钢琴学习、合唱排练和伴奏经历，使我很在意几个人能不能真正听到彼此、合到一起。我曾做基于时间码的多乐器异地MIDI合奏，处理各端时钟和网络延迟不同造成的困难。后来把注意力转向课堂，我发现，技术把声音传到学生面前只是第一步。同一段音乐，教师已经指出了问题，有的学生知道接下来该听什么、练什么，有的学生却只是把原来那一遍再重复一次。程序可以告诉他哪里不一样，却不一定能让他知道为什么不一样。我不想把这种差别简单归为学生认真与否，也不想用一个准确率分数把它遮住。

目前这套系统已经把乐谱导入、音乐播放、自然语言操作、跟弹练习和曲谱课堂串在同一工作区里。教师可以导入PDF、拍摄的谱页、MusicXML、MIDI以及音视频材料，核对原稿与电子谱，再围绕当前作品开展聆听、声部比较、课堂问答或练习。做这些入口不是为了让软件的功能表更长，而是因为真实教学里的材料本来就不整齐：学生带来的可能是一张歪斜的谱页，老师保存的可能是一份多轨MIDI，课堂要用的也可能只有录音。不同材料进入系统以后，需要尽量保留原来的音乐关系，同时让教师看得到识别和转换的局限。

这件事最费工夫的地方之一，是把“看起来像一份谱”的结果处理成真正可以教学使用的音乐对象。以MusicXML为例，小节里的多个声部并不是按文件顺序依次发声，backup会让书写时间回退，chord说明音符同时发声，谱表与声部也不是同一概念。如果处理错了，左右手会串在一起，和弦会变成依次播放，谱面没写休止却会每小节空出几拍。MIDI又有另一类困难：它记录的是演奏事件，音轨、通道、音色和速度变化需要保存，不能为了方便显示就全部压成一架钢琴。我曾反复遇到谱面、播放和课堂解释彼此不一致的问题。这让我意识到，识谱错误不是前端一个孤立故障，它会继续传到音响、AI分析与学生评价里，最后变成教师也不容易察觉的错误依据。

因此，我把作品、版本、小节、声部和时间位置作为模块之间需要共同核对的信息。原稿PDF、五线谱、简谱和音轨视图应该呈现同一段音乐；切换视图不应改变声音，选择独奏也不应让作品从头开始。PDF上框中哪一小节，需要结合谱表、小节线和缩放坐标，不能只按页面横向等分；跟随播放也不能让界面抢走学生的操作权。它们看似是细小的交互问题，但当学生正要比较两次出现的主题时，如果位置跳错、播放中断或界面跟不上，原本可以连起来的听觉判断就被打断了。我希望研究的不只是反馈内容，还包括反馈能否在合适的时刻，以不破坏音乐连续性的方式出现。

项目中我最想向您详细汇报的是AI Agent和曲谱课堂。对于Agent，我并不满足于让它回答“可以独奏弦乐”。它需要知道当前是哪份作品、用户所说的“刚才那一段”指哪里、这份谱里到底有没有独立弦乐轨道，然后调用播放器，确认真正发生了什么，再继续对话。如果不存在那个声部，它就应该说明，而不是把一句成功提示当作完成。系统为此把自然语言请求转换成有限动作，对范围和参数进行校验，并让执行结果返回后续交互。曲库查找、选择作品、定位小节、独奏静音、调整速度和练习安排由此可以接在一起；音乐分析则需要回到真实谱面，不能只凭曲名调用一段印象式介绍。

对音乐教学来说，这种能力有一个具体用途：把学生的问题变成可以当场检验的声音操作。例如学生说第二段更有推进感，教师可以追问“你觉得是旋律变了，还是伴奏变了”，再让学生选择要独听哪一层。系统负责找到片段、维持相同速度、切换可听声部，学生负责提出判断并说明依据。听完以后也可以发现自己的猜测不成立。我更在意这样的过程，而不是让AI一次性把“正确分析”写得很长。只有允许学生先提出不完整的解释，再通过声音修正，技术才可能参与理解的形成。

曲谱课堂是在这个基础上继续做的。它接入生成式课堂组件，但我主要处理的是通用课件生成进入音乐教育以后不自然的部分。高中音乐课不能自动变成钢琴个别课，普通学生也不应因为不会弹琴就无法参与。生成条件因此要包含学段、课时、当前作品、所选范围、教材与教师目标；课堂内容需要落实到聆听、歌唱、律动、比较、讨论和合作编创。PPT上的“聆听30秒”不能只是几个字，讲解结束后要真的播放对应片段，播放结束后再继续提问。互动页面中的“只听低音”也必须控制当前音乐，而不是只改变页面图标。教师能够修改局部讲稿与课件，不必为了纠正一句话重做整节课。

课堂执行中还有很多不容易在演示里看出来的问题。内容生成完成不等于声音开始播放；声音还在下载时，如果系统已经把状态标成“正在讲解”，教师会以为设备坏了。课程生成中途断开，也不应该让已经准备好的内容全部丢失。切换曲目以后，旧课程晚到的回复必须停止，不能把旧作品的小节带进新课堂。我把这些问题逐步转化为状态校验、分环节保存、版本关联和可重试的任务。对我来说，它们的价值在于保护教学的连续性，也让研究时可以区分：学生没有完成任务，是不理解音乐，还是系统根本没有把材料呈现给他。

这些工作使我逐渐区分三种不同的判断。音高、时值和声部归属属于需要校对的谱面事实；作品的情绪、结构功能和风格属于需要声音与背景材料支持的音乐解释；学生是否理解、是否形成能力，则必须通过其行为和新的任务验证。系统不能从其中一层直接跳到另一层。例如，听出一次低音变化不等于已经理解整个曲式，机器记录了更多正确音符也不等于演奏更有表现力。当前系统已有一些局部事实校验和真实动作回执，但我不会把它写成能够替教师完成全部音乐判断的工具。

过去一年在星海高中的实践，让我更关心技术进入真实班级后的变化。一个班里，有的学生有器乐基础，有的主要通过流行音乐积累经验。即使给他们同样的提示，他们注意到的内容和采取的办法也可能不同。我想认真追踪的，不只是他们最后答对没有，而是他们有没有主动回听、选择了哪个片段、为什么改变原来的回答，以及教师在哪一步补了一句关键的话。原来我容易把“提供了反馈”当作工作完成，现在更想知道反馈被怎样使用。课堂资料、实施范围与数据仍需要进一步整理，申请时我会据实提交，不能把平台能产生记录等同于已经形成完整的研究数据集。

跟弹练习提供了另一个更细的观察入口。系统从麦克风获得起音与音高候选，再与当前乐谱匹配，可以形成小节层面的偏差摘要。但环境声、踏板、复音和设备差异都会影响识别，所以我没有理由把每一个未匹配音都解释为学生弹错。对这部分，我希望先建立人工核对的样本，区分识别错误与演奏偏差，再研究反馈安排。同样是一处问题，立即给出具体错音、先让学生自评、只提示一个小节、演奏结束后再汇总，这些做法可能带来不同的练习行为。我最想看的，是学生会不会从无目的的整段重复，转向有判断的局部练习；当提示被撤掉以后，这种改变还能不能留下来。

生成练习素材与配器也是这个项目的一部分。我的目标不是让模型任意续写，而是让生成接受调性、声部、织体密度、音域与演奏难度等约束，再把结果放回播放器和谱面核对。同一旋律配以不同伴奏，可以成为课堂比较的材料；不同难度的版本也可能支持不同基础的学生参与。但我也遇到过配器虽然符合输出格式、听起来却很嘈杂的问题。这说明“生成成功”离“音乐成立”和“适合教学”还隔着几层评价。我希望把这种失败也留下来，分析到底是和声依据不足、声部进行不合理，还是适配和播放出了问题，而不是只展示最好听的一次。

我也想把材料进入系统后的几条不同路线交代清楚。五线谱PDF先按页识别，再归一为保留声部和时值的MusicXML；简谱则要先读取数字及调号，再检测数字上下的八度点、下方减时线和延长记号，最后才确定实际音高与时值。一张简谱上看似很小的点，决定的可能是整整一个八度，不能当作普通文字识别的噪声去掉。照片先保留页序并整理成文档，音视频则经过音符转录再做节奏量化，这两条路线不能混用。音频里检测到一个起音，是声学判断；把它记成附点、三连音或跨小节延音，是音乐结构判断。我在这个地方尤其谨慎，因为量化出来的谱可能很整齐，却已经不是原来那段音乐了。

原稿核对也有具体的技术困难。系统在原始页面中检测五线谱水平线、小节线和谱表之间的连接，得到候选小节矩形，再与结构化谱的小节建立对应。这样才能让教师点原稿时听到相应片段，也能在演奏时显示正在经过的位置。但检测少了一条小节线，后面的编号就可能一起偏移，所以我不能把“画出了色块”当成“定位已经准确”。我希望保留原稿、结构化结果和映射关系，让错误有地方可以追查，而不是让学生只面对一份已经被程序改写、却不知道改了什么的谱。

声音这一侧，我逐渐把音源、表情和时间调度分开处理。钢琴采用不同触键强度的采样层，让力度变化既影响响度，也影响音色；其他乐器按照轨道身份调用音源，鼓组独立记谱和发声。演奏表情模型提供起音、持续和力度候选，但必须先核对它有没有改变音符数量和音高，再限制相对原谱的时间偏移。我不希望“自然”成为节奏不稳定的借口。尤其在多声部合奏和教学示范中，一个声部自由伸缩、其他声部却仍按原时钟走，会把本来清楚的音乐关系破坏掉。人声绑定同样如此：整体抢拍可以通过起点微调修正，越唱越偏则需要检查速度关系，不能靠播放中不断跳转音频来追赶，否则就会出现断续。

对生成的配器，我目前采取的是先产生候选，再依据原谱约束的方式。系统按音乐时间窗口统计实际持续的音，结合乐器音域、相邻音移动、声部间距和与旋律的关系筛选候选；同音连接可以合并，过密或明显冲突的候选可以舍弃。鼓组从拍号和乐句位置建立脉动、重音与转折，而不是钢琴弹一下就打一下。这里还有我没有想通、也值得进一步研究的部分：规则可以减少明显冲突，却可能把风格上有意味的紧张关系也删掉。怎样区分需要纠正的错误和应当保留的音乐表达，需要音乐分析和听觉评价共同参与，不能只靠程序判断。

跟弹中的指法与三维手型也让我更清楚地看到示范的边界。指法需要考虑键盘距离、手指跨度、连续动作以及和弦条件，当前方案是在有限前瞻范围内搜索较合适的候选，再绑定到具体音符。三维手型把这些指法转成琴键上的指尖目标，利用手指骨骼长度求解姿态。我会把它作为帮助理解的可视示意，而不把它当作已经得到钢琴教学验证的标准动作；仅仅让指尖碰到琴键，并不说明腕部转移、跨指和触键方式正确。这样的区别恰恰需要我的音乐教育训练来把关。

为保证一节课能够连续进行，我还把不少时间花在不容易被演示画面看见的地方。上传和识别由服务端任务管理，页面关闭后仍能找到结果；同一份文件可以复用识别结果，但谱面内容或教学条件改变后，旧课堂不能继续冒充新结果。课堂生成按提纲、页面内容与动作分阶段保存，已经可用的部分先出现。生成的小游戏通过消息接口控制真实播放器，操作结束后回报实际状态，而不是在自己的小窗口里播放另一段声音。语音按教师、学生和语言分配角色，提前准备下一片段；页面也要区分“准备好了讲稿”和“用户已经听到声音”。这些细节直接决定课堂能否把注意力留在音乐上。

项目的数字人介绍同样接在这套时间与状态管理中。照片关键点参与面部拟合和纹理定位，角色根据讲解阶段看向黑板、做指示与离场；音频驱动嘴部开合，固定正文优先使用已经确认的合成资源，只有访问者姓名问候需要即时生成。音色实验又区分参考声音推理、局部参数适配与声学模块训练，不能把它们笼统称为重新训练了一个完整模型。三维人物完成介绍后立即释放渲染资源，才能把设备能力留给随后打开的大型曲谱。对我而言，数字人可以改善进入项目的体验，但研究中心仍应是学习活动及其证据，而不是人物看起来有多像真人。

这也是我对博士阶段研究问题的初步界定：在音乐学习中，怎样安排有谱面依据、能够落实到声音操作的智能反馈，才能帮助学生形成独立的聆听判断和练习调节能力？我想把问题收得足够具体，不以“人工智能赋能音乐教育”作为最终答案。首先需要验证系统能否正确执行教师与学生的音乐意图，建立包含错误恢复和连续指代的任务集。然后在相同作品、目标与时间条件下，比较仅有解释的支持与能够操作真实音乐材料的支持。最后设置不提供提示的新片段和延迟任务，检验学生是否只是记住了当前回答。学生的基础经验、教师介入和实际聆听时长都需要记录，不能把这些影响全部归给AI。

在研究方法上，我希望把课堂观察、学生解释、实际操作日志和作品表现放在一起。过程数据能告诉我学生何时重听、何时请求帮助，但不能单凭点击推断认知；访谈能补充他当时在想什么，却也需要与行为核对。对班级共同使用的设备，日志只能说明全班经历了什么，不能擅自分配给每个学生。对学习结果，我希望请独立教师根据音乐证据定位、解释关系和迁移表现进行评分，并检查评分一致性。样本规模不足时，就诚实地把研究做成深入的设计研究和案例分析，而不通过重复点击数制造大样本。作为开发者同时参与教学，我也需要外部观察和评分，避免只看到自己系统有效的地方。

我现在更想追踪的是学生怎样参与这套系统。音乐中的互动不仅是对话，重新听一次、唱一遍、改变伴奏再作判断，同样是有意义的回应。怎样把这些回应和语言放在同一研究框架中，又不把复杂的音乐经验压缩成几项机器分数，是我希望继续深挖的地方。现有系统让我有条件把教学假设做成可操作的安排，但这些安排是否有效，仍需要严谨研究。这是我希望读博的原因，而不只是希望给软件增加更多功能。
