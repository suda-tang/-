# 开场全屏、讲解就绪及云层退场

## 根因

开场全屏布局依赖异步CSS，网络较慢时画布会先继承普通组件尺寸。首段语音缓冲曾允许在12秒后强制视作就绪；个性化问候也曾在10秒后回退。这会让镜头已进入校园，音频还没能播放。音轨清单请求8秒超时后会只留下一个兜底音轨，导致显示1/1。云层退场绑定整个古城加载状态，而不是镜头所处位置。

## 调整

开场容器及宿主的全屏布局同步设置，第一帧渲染就按视口尺寸初始化。完整七段音轨清单随轻量模块交付，不会因JSON请求失败退化为单段；后续发布新语音时同步重建这个模块。姓名问候和音频请求仍从HTML入口提前发起。仅在实际可播放且首段已缓冲至少1.5秒时允许校园进场，不再用超时假装就绪。工作区模块下载推迟至导师实际发声之后，退出或错误仍可释放这道等待，防止退出流程死锁。浏览器若要求手势，进入动画时的触摸可提前解锁并缓冲音频。

云层在校园进场阶段淡出，校门开始打开时强制不再绘制云层，不等待无关古城资源。当前七段之后的音频仍在上一段和转场期间预取；网络完全中断或服务器不可用时无法承诺无等待，也不会以隐藏错误来伪装完成。

## 验证

`check-mentor-entrance128.cjs`使用390×844触摸视口：延迟CSS、拦截原JSON音轨清单、暂缓语音响应；检查第一帧之后的画布尺寸、语音未就绪时不进入校园、校门打开时无云遮挡、最终显示第1/7段且声音实际播放。另运行转场延迟恢复测试，确认页面恢复/点击不会绕过等待或产生分身。
