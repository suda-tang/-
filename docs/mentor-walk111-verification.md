# 园林连续行走及转场修订记录

日期：2026-10-21。发布缓存版本：mentor-garden-walk114-20261021。

## 变更

钟楼出发路径取消前院折返和重复绕侧面，经过安全转角后直接进入通往园林的航段。镜头中段朝路径前方，起止方向平滑衔接，保持水平，不做周期侧倾。相同避障条件下，第一条测试航线由约148.57米缩短至131.81米。

园林外底板原来只按薄板几何筛选，遗漏了拙政园厚底座及其侧面。现在对低位几何应用独立的内缩轮廓遮罩，并分别识别底座高度和水平铺装；保留真实围墙、台阶和内部铺装。两座园林分别生成底板遮罩，不再直接复用包含外沿的建筑轮廓。

步行路线从实际模型的干燥铺装采样生成，剔除低位池水和假山，转角使用圆滑过渡。人物、镜头使用同一预计算路线和时间表；同时限制人物速度、加速度及镜头速度、加速度。在转角和狭窄区域平缓减速，不再运行时临时搜机位，也不再按固定周期停步折返。步态按真实位移推进，脚、膝、腿只由一套步行动画驱动。人物转身有角速度限制。

镜头路线的离线生成考虑实际模型三角面及植被透明纹理，避免把透明叶片矩形全当成实体。连续避障检查补充镜头扫掠体和细小树冠边角的相交测试，不能仅依赖稀疏点采样。浏览器读取已生成结果，不在每帧扫描整座园林。

## 验证

- 15个模块语法检查通过，外网导览、步行模块、避障档案内容与本地发布文件一致。
- 六段飞行各601次采样，碰撞数为0；路径计算放在Worker中，主线程计时器持续运行。
- 两座园林连续路线检查：镜头碰撞数0，人物越出裁切后地面数0。怡园路线约16.06米、37.72秒；拙政园约18.26米、68.18秒。
- 同一时间表下，采样镜头最高速度约0.71米/秒、1.32米/秒；没有瞬时跳机位。
- 厚底座及其侧面像素测试通过，并另行渲染真实拙政园模型对照，确认外围白色底板被裁去，围墙仍保留。
- 转场朝向与路径前进方向一致；旧脚部动画抢写回归测试通过；狭小障碍连续相交测试通过。

完整页面录制使用Windows Edge的390×844移动视口，两座园林均走到路线终点，未报告模型加载或飞行规划错误；记录1048帧，连续步行阶段采样镜头最高速度约1.28米/秒。该记录不等于实体iPhone Safari帧率测试。录制和截图保存在`.sites-runtime/mentor112-video/`、`.sites-runtime/garden-model-research/`。

完整录制发现实际怡园终点与固定航线测试起点不同，宽体积巡航规划会拒绝拙政园入口的有效机位。已增加普通镜头和园内步行镜头的逐级规划，转场中段优先使用普通镜头体积，校园开阔航段仍保留较宽间隙。新增`check-garden-real-transition.cjs`，使用实际联合路线两端进行连续扫掠检查，671个路径点通过，碰撞数0。修复后的整段页面录制可完成怡园至拙政园转场。

## 重建顺序

后续巡检：七段实际页面场景均抵达，无模型加载、飞行规划错误。划船上岸测试完成，人员落到岸上地面且资源正确释放。标牌落位不再对整块园林的InstancedMesh逐实例射线扫描，而是复用附近实例代理缓存；一万远处实例夹具中整批射线调用为0，缓存后20轮查询平均约3.1毫秒，附近真实障碍仍阻止落位。该耗时是本机合成测试，不是手机帧率承诺。

已有源几何、高度缓存和步行掩膜时，运行`build-garden-smooth-walks.py`生成候选走廊；运行`build-garden-promenade-rails.cjs`生成带碰撞及可见性检查的联合路线，构建器自动调用`retime-garden-rails.cjs`生成速度时间表。底板轮廓通过`build-garden-base-masks.py`生成。

相关检查脚本：`check-garden-smooth-rails.cjs`、`check-mentor-garden-paving.cjs`、`check-garden-motion-regressions.cjs`、`check-mentor-obstacle-corners.cjs`、`check-garden-base-trim.cjs`、`check-garden-real-base-visual.cjs`、`check-mentor-worker-flight.cjs`、`check-garden-walk-video.cjs`。
